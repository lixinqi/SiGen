# 评估方案

这份文档给出可复核的评估口径，用于回答一个问题：加了预判、去重和自更新之后，系统是否真的比更简单的方案发现更多有效产物，且代价可接受。结论允许为负；方案本身不预设结果。

## 主结果

评估以有效性为口径；比较型任务里，“有效”即“被测侧相对对照存在超过阈值的稳定差距”。主指标定义为：

> 每单位真实实验成本，环境评估确认的独立、可复现、有定位证据且具现实代表性的有效发现数量；比较型任务即短板根因数量。

四个限定词都不可省略，缺一项就会让数字失真。

- **独立**：按版本化的根因归并规则去重后的数量。两个测试命中同一机制，计为一次。归并规则本身有版本，改动规则需要重跑历史数据，不能只在新数据上适用。
- **可复现**：在独立复验中稳定出现，且条件明确（版本、负载参数、初始状态、环境）。
- **有定位证据**：能指向具体机制或至少一组可复核的资源与轨迹证据。只有差距没有解释的，归入未确认行为簇。
- **具现实代表性**：负载在业务上可解释，不是仅靠畸形参数制造的极端差距。

未确认行为簇单独计数，不并入主结果。它是“可能有价值但尚未定性”的库存，用于观察定位环节是否成为瓶颈。

## 成本口径

必须同时报告三种成本，且都计入分母。

- **机器成本**：两侧配对执行、状态复位、重复测量、复验、失败重跑、审计样本。
- **模型成本**：生成、预判、去重判断、审核、根因辅助分析。
- **人工成本**：根因确认、协议设计、异常排查。

只报机器时间会系统性高估效率：审计与定位往往消耗人力而非机器。对照组之间若机器预算相同但人工差异很大，应分别列出，不能用一个“等预算”抹平。

成本单位建议固定为配对机器秒，模型成本按实际调用折算，人工按记录工时折算；折算率在报告中写明并保持一致。

## 对照组设计

四组逐层加入能力，全部在相同任务、相同机器预算、相同审计份额下运行。

| 组 | 组成 | 回答的问题 |
| --- | --- | --- |
| E0 | 固定生成器，候选全部真实执行 | 基线：不做任何筛选能发现多少 |
| E1 | E0 加预判与统一调度，保留探索与审计 | 前置判断与预算分配是否提高单位成本发现 |
| E2 | E1 加语义去重与行为对照 | 减少重复投入是否提高独立根因产出 |
| E3 | E2 加生成器更新 | 生成策略学习是否带来额外发现 |
| E4 | E3 加判定组件与审核器更新 | 元层的自更新是否有可测量的贡献 |

E1 到 E4 的增量是分开报告的，不合并成“全系统对比 E0”。全系统对基线的比较只能说明整体是否有效，不能说明哪一层在起作用。

**E4 的分解更细。** 至少要区分三种更新：预判器更新、去重器更新、审核器自更新。审核器自更新的贡献需要用“冻结审核器版本”的对照来估计，否则它的作用与预判器更新混在一起。

## 每一层的判负条件

结论必须允许被证伪，判负条件在实验开始前写好。

- E1 在相同机器预算下的主指标不高于 E0：预判调度无收益，预判器最多保留为分析工具，不应参与筛选。
- E1 的主指标上升但审计估计的漏报率超过预设上限：收益来自缩小搜索面，不是来自更好的判断。
- E2 不高于 E1：语义去重没有减少浪费，或去重误合并抵消了收益。
- E3 不高于 E2：生成器自更新没有带来新根因，只是更快地重复已知模式。
- E4 不高于 E3：元层更新无增量，保留静态晋升规则更省事。
- E4 的主指标不升但退化指标改善：审核器学会了保守，不是学会了审核。此时应单独报告“拒绝率”和“被拒绝后经审计试行证明有价值的比例”。
- 任一组的覆盖指标（执行过的负载族数、参数区间）显著低于对照组：即使主指标上升，也视为搜索面收缩，需人工检查。

## 选择偏差与审计

审计的设计决定漏报能否被估计，因此需要单独说明。

- **抽样总体是原始合格候选**，不是模型通过的子集。审计必须能越过预判与去重的软否决。
- **审计按最终入选概率加权。** 每个被审计对象记录它的边际入选概率；审计样本的报告要按概率重加权，否则估计的是“被审计者”的表现，不是总体的表现。
- **高置信否决必须有非零审计概率。** 若某个区域入选概率为零，则该区域的漏报不可估，必须在报告中声明覆盖缺口，而不是给出一个总体漏报率。
- **误拒绝审计针对更新。** 被延后的更新保留待复核队列，按预算抽一部分进入试行；其后续版本对照结果与原始审核判断一起记录。审核器的误拒绝率只能由这部分样本估计。

审计份额的建议起点是总预算的百分之十到二十，具体按任务调整；份额变化会改变主指标，因此任何跨期比较都必须固定份额。

## 统计要求

- **配对与交错。** 两侧执行同一业务语义，顺序交错，避免一侧长期占用更好的机器状态。
- **重复与噪声。** 重复次数由实测噪声决定，且写进协议；预判器给出的区间不参与显著性判断。
- **实际意义阈值。** 差距要同时超过统计噪声与业务阈值。只显著但没有实际意义的差距不进入发现集合。
- **多重比较。** 逐个候选反复检验会放大假阳性；协议需说明校正方法或序贯停止规则。看到结果再决定是否重跑，等同于事后选择。
- **失败处理。** 编译失败、工作不等价、环境失效、无法归因的超时，都不构成负样本。它们记录为无效执行，可用于改进候选有效性，不能用于训练“无短板”。
- **无结论保留。** 区间跨越阈值时返回无结论，等更多样本或复验，不强行二分。

## 版本与漂移

被测系统和对照系统都在变化，“不遗忘”并不总是正确目标。

- 每个标签绑定目标版本、对照版本、配置、硬件与协议。版本变化后，旧标签默认失效，需要重新验证；可迁移的部分要显式标注适用范围。
- 曾经确认的短板在修复后应能被重新检验，旧标签不能继续支配预测。
- 窗口对照必须使用当时的基础版本，不能用“上一季度平均”充当对照。
- 环境漂移需要监测：若两侧的绝对性能同时发生同向变化，应先排查环境，再解释相对差距。

## 必须随结果报告的数字

只报主指标不足以让人复核判断，下表是最小报告集。

| 项目 | 口径 |
| --- | --- |
| 已确认根因数 | 独立、可复现、有定位证据、具代表性 |
| 未确认行为簇数 | 有差距但无定位证据，单独计数 |
| 总机器成本 | 含审计、复验、失败重跑 |
| 总模型成本 | 按实际调用折算 |
| 总人工成本 | 按记录工时折算 |
| 执行覆盖 | 负载族数量与参数区间 |
| 审计样本量 | 按最终入选概率分层的实际执行数 |
| 估计漏报率 | 仅在覆盖非零区域给出，并标注适用范围 |
| 审核器拒绝率 | 延后更新占全部待审更新的比例 |
| 误拒绝后证明有价值的比例 | 仅由审计试行样本估计 |
| 置信度校准误差 | 按命题、按组件分别报告 |
| 版本切换次数 | 晋升、恢复、待决各计一次 |

## 威胁与局限

- **审计预算有限。** 漏报率是估计值，置信区间随审计样本量变化；样本太小时只能给出方向性判断。
- **选择偏差只能部分纠正。** 概率重加权对零概率区域无效；生成侧未覆盖的负载族仍是盲区。
- **根因归并带主观性。** 归并规则的版本化能保证一致性，不能保证正确性；跨团队的归并结果可能不同，报告需写明规则版本。
- **窗口信用分配稀疏。** 一个窗口对应多个改动时，归因依赖消融或回放；做不到时应报告“尚不能归因”，不计入任何一组的增量。
- **过拟合评估本身。** 长期在同一批负载族上调参，会把“适应评估集”误当成“提高发现能力”。需要保留未见族作为最终检验，并在报告中说明它们从未参与更新。

## 一次完整评估的流程

1. 冻结任务、协议、预算、审计份额与判负条件，写入可查记录。
2. 建立 E0 基线，记录全部原始观测与成本。
3. 逐层加入组件，每层只引入一个主要改动；同时改多项时安排消融。
4. 每层结束后先看主指标，再看覆盖、漏报、校准与拒绝率；出现覆盖收缩即暂停并检查。
5. 对每组做未见负载族的迁移检验，单独报告。
6. 按报告清单出具结果，包含判负的组，不做选择性呈现。
