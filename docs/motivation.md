# 动机与取舍

这份文档解释 SiGen 为什么采用现在的形状。它不重复 README 的流程说明，而是处理几个容易在评审中被问到的问题：问题究竟难在哪、朴素方案为什么不够、哪些看似合理的简化被否掉了、什么条件下这套设计不成立。

## 问题的形状

要被搜索的对象是“能被环境反馈确认有效的实验产物”，比较类任务里即“能暴露相对短板的测试”，而不是一段能编译的代码。一次实验包含代码、参数、初始数据状态、并发与持久化要求、测量目标；一次可信的结论还需要配对执行、重复测量、正确性校验和版本记录。候选可以无限生成，可信结论不能。

这类问题有三个特征同时出现。

**真值昂贵且可重复。** 一次运行要占用两台系统的资源，要复位状态，要重复到能区分噪声。但同一实验可以重跑，结论能在给定条件下复核，这使它区别于依赖人类评分或另一个模型打分的任务。

**真值稀疏。** 大多数候选不会暴露差距。若把预算平均铺在所有候选上，绝大部分成本换来的是“没有发现”。

**判断可以前置，但不保证正确。** 代码与负载语义里确实存在可迁移的规律：目录规模跨过某个阈值、并发 rename 与 fsync 的组合、冷热缓存差异，往往反复影响两侧的相对表现。可迁移不等于可靠，模型在没见过的负载族上会错。

因此这是一个“在昂贵真值上做主动搜索”的问题，而不是“让模型自己写更多测试”的问题。前者关心每次运行换来多少新信息，后者只关心产出数量。

## 朴素闭环为什么不够

最基本的闭环是生成、两侧运行、筛出差距、把结果反馈给生成器。它有一个不可替代的优点：裁决来源是物理运行。它的问题出在预算分配与经验积累上。

**第一，它把预算当成均匀资源。** 没有前置判断时，绝大多数运行花在没有差距的候选上；有前置判断但只运行判断为真的候选，又会把判断的错误藏起来。

**第二，它容易反复确认同一个现象。** 生成器学到“某类负载容易出差距”之后，会大量生产同类变体。参数改一点、循环换个写法、文件数加一档，都能通过“是否新代码”的检查。发现数量上升，独立根因没有增加。

**第三，任何硬过滤都会切断自己的反馈。** 预判器把某批候选判为不会有差距，这批候选就不再执行，于是预判器永远不知道自己漏了什么。生成器随后只生产预判器偏爱的负载，预判器在越来越窄的分布上被评估，准确率可以持续上升，覆盖却在收缩。审核器有对应的问题：被它拒绝的更新如果不再试行，它只见过“放进来之后坏了”的案例，没见过“拒掉之后本来会好”的案例，最省力的进化方向是越来越保守。

这三个问题里，第一个可以靠调度解决，第二个要靠语义去重，第三个要靠把探索写进决策接口。三者都不需要否定物理真值，只需要不再让模型判断直接等于执行决定。

## 为什么不把三种判断合成一个分数

系统里有三种判断，它们看起来都是“这个对象值不值得投入”：

- 预判器判断“在这个协议下，环境反馈是否会确认该产物有效”，比较型任务里即“是否存在超过阈值的稳定差距”；
- 去重器判断“相对指定代表，这个候选是否提供已有证据不能替代的实验信息”；
- 审核器判断“这次更新是否在指定对照窗口中满足收益与能力保留条件”。

把它们压成一个“综合分数”会立刻遇到三个问题。

**命题不同，标签不能互借。** 测试是否有效由环境评估回答；测试是否冗余由行为对照回答；更新有没有收益由版本对照窗口回答。用测试的阳性结果去训练去重器，等于把“这个测试有价值”当成“这个测试不冗余”，而同一根因可以由多个互不冗余的测试命中，一个冗余测试也可能恰好落在差距大的参数点上。

**方向不同，量纲不同。** 短板概率是“命题为真的可能性”，更新收益是“相对基础版本的净效应”，去重关系是“信息可替代性”。相加需要一个共享单位，而这个单位不存在；强行归一化只会把不可比的量藏进权重里。

**成本不同，动作不同。** 预判是廉价的推断，测量是昂贵的执行，试行更新是以周为单位的窗口。一个统一阈值无法同时适配这三类动作；真正的预算约束发生在调度器，而不是发生在分数上。

统一接口因此只统一两个量：`value` 是命题概率，`confidence` 是这类估计的经验可靠性。两者都必须绑定命题、模型版本和协议。统一的是决策形态，不是判断内容。

## 统一接口为什么仍然有意义

如果三种判断不能混，为什么还要统一？

因为三种判断面对的是同一个结构性问题：模型有偏好，模型的偏好会改变它自己看到的世界。统一接口让“判断、经验边界、探索、结果回流”成为同一套动作，而不是给每个组件各写一套外挂补救。

具体收益有三点。

**探索可以被预算。** 置信度低的对象提高执行概率，高置信否决保留小概率审计；审计份额在处理整批候选时先预留，再按最终入选概率分配。这样误拒绝的代价从“永久损失”变成“以已知概率付出的探索成本”。若没有统一接口，每个组件都要自己发明一套抽样规则，预算无法合并核算。

**经验可以按命题校准。** 置信度不由模型自报，而由留出的有效历史检验。三种命题各自校准、各自记录案例，不共享标签。统一的是校准机制与其输入结构（案例、协议、入选概率、独立组），不是标签。

**错误可以归因到具体一层。** 一次“该跑没跑”和一次“跑了没用”在记录上是不同的事件：前者是选择路径造成的延期，后者是有观测的负结果。若把两者压成一个分数，归因就只剩下“模型不准”这种无法改进的结论。

## 置信度为什么必须外部校准

让模型在输出里附带一个“我有多确定”，是最省事也最没用的做法。语言上的确定性与统计上的可靠性没有关系：模型可以在完全没有同类经验时输出高置信，也可以在经验充足时因为措辞谨慎而输出低置信。一旦置信度可以自报，探索机制就失效了，因为系统总能给自己一个不需要探索的理由。

因此置信度要由共享的校准过程给出，输入是四类信息：同类对象的历史案例、当时的原始预测、验证协议、以及每个案例的最终入选概率。方法上需要按行为组和时间留出，否则同一逻辑的多个变体分散在拟合与验证两侧，可靠性会被高估。

这里还有一个容易忽略的量：**只有记录了最终入选概率，历史案例才是可用的样本。** 如果经验库里只有“跑过的对象”，那么这批样本已经被预判、去重和预算三重筛选过；用它计算出的命中率不能代表模型在全体候选上的表现。选择概率是后续纠正选择偏差的唯一入口，它必须在选择发生时写入，不能事后补算。

## 去重为什么要放在预判之后，又为什么不能只做一次

把去重放在预判之后的理由很实际：预判是廉价推断，可以先缩小需要精细比较的范围；去重需要参照集合与语义比较，成本更高。

但去重只做一次是不够的，因为“重复”在三个层面上含义不同。

- **代码层**：源码相同或只改名字，可以直接判定为同一对象，属于廉价前置去重。
- **行为层**：代码不同但访问轨迹、状态变化和性能响应可替代，这是运行前的语义判断。
- **根因层**：两次发现是否指向同一个机制，需要运行后的定位证据。

三层之间存在一个不能反推的方向：同一根因可以由多个行为不同的测试暴露，因此“根因相同”不能证明“运行前两个测试冗余”。把根因归类当成去重标签，会让系统丢掉能定位同一机制的不同入口，也会让去重器在没有行为证据时拿到一个看似正确的标签。

这也是去重器需要额外验证的原因。候选一侧出现差距，只能说明它有价值，不能说明它相对某个代表提供了新信息；判断冗余需要候选与代表在可比条件下的行为对照。没有代表观测时，正确结论是“无结论”，而不是“保留”或“删除”。

## 更新为什么不看前后指标

自进化系统最诱人的评估方式是：改一版，看接下来一段时间的发现率有没有上升。这个比较几乎总是错的，原因不在统计细节，而在混杂。

**任务在变。** 上一窗口跑的是简单负载，下一窗口遇到的是难负载；发现率下降可能说明系统变差，也可能说明容易的问题已经被找完了。

**环境在变。** 被测系统在持续开发，对照版本也在更新，机器状态、依赖版本、数据分布都会漂移。

**多个改动同时在生效。** 一个窗口里可能合并了生成器、预判器和去重器的修改，前后差异无法分配给其中任何一个。

**定义可以被改动。** 如果候选版本能修改成功口径、样本筛选或指标计算，它就可以通过改定义来证明自己有效。

因此更新必须与基础版本在同一窗口、同一任务、同一预算下对照运行，并且成功口径在窗口开始前冻结。做不到这些时，正确输出是“尚不能归因”，而不是一个偏向正面的结论。

## 为什么不把审核器隔离出去

一个直觉是：既然审核器要给其他组件打分，就把它放在仓库外面，避免它被待审代码影响。这个做法能防住一类作弊，代价是失去最有用的诊断材料。

审核器要判断的很多问题，只有能看到实现才谈得上判断：这次差异有没有改动自己的否决逻辑、有没有改变样本筛选从而改变评估分布、有没有把指标计算改成对自己有利、有没有让生成器只覆盖某一类负载。把审核器隔在门外，这些只能靠提交者自述。

所以边界不设在“能不能看”，而设在“能不能改已经发生的事实”。审核器可以读自己的源码、判断轨迹和历史差异，但不能重写原始观测、旧判定、旧协议，也不能在这次窗口里替换掉作出原始判断的版本。审核器修改自身时，原始判定仍由旧版本给出，新版本只影响之后的判断。

这条边界不是道德约束，而是使“改进”这个词保持可检验。若当前版本可以重新定义什么叫成功，任何自我修改都能自称有收益。

## 被否掉的几种简化

**只运行预判为真的样本。** 省成本最直接，也最快把系统变成自我确认。审计样本必须能越过两个模型的软否决，否则漏报率不可估。

**审核器输出布尔值，再靠事后抽样复审补救。** 这等于把探索放在流程之外：复审由谁触发、预算从哪来、结果如何回流都没有进入接口，实际运行时最先被砍掉的就是它。

**把三个组件拆成三个各自追求目标的 Agent。** 拆分本身不增加信息。真正需要区分的不是角色，而是命题、标签和预算。去重器更合适的定位是一个可进化的相似度模型与覆盖控制器，为调度提供距离与受控变体信息，而不是一个独立发号施令的实体。

**以“没有退化”作为成功标准。** 永不更新即可满足。必须同时报告发现收益，并单独衡量过度保守。

**以“预判准确率高”作为成功标准。** 在收缩后的分布上，准确率可以任意高。必须报告覆盖、审计估计的漏报和独立根因增量。

**用预判器预测的方差决定显著性。** 这会让模型的自信程度影响实验结论。显著性只能由实测噪声和事先冻结的协议决定；预测区间是给调度用的，不是给测量用的。

## 什么条件下这套设计不成立

设计有明确的适用边界，越过边界后收益会被成本吃掉。

- **真值不可重复。** 若同一实验在不同时间给出系统性不同的结论，且差异无法归因到版本或环境，环境评估无法提供稳定标签。
- **实验会破坏共享状态。** 需要生产数据、不可回滚的外部系统、或无法隔离的资源时，探索性执行的风险高于收益。
- **两侧不可比。** 目标与对照在执行同一业务语义时无法对齐（例如一侧必须改变工作内容才能运行），差距就失去解释力。
- **预算不足以重复。** 没有重复就没有噪声估计，没有噪声估计就无法区分差距与波动，此时系统只能产生猜测。
- **任务本身太窄。** 若候选空间小到可以穷举，全量执行比建模更省事，预判与去重都是额外复杂度。

在这些条件下，系统仍可做记录与诊断，但不应宣称在“发现短板”。

## 代价与未解问题

诚实地说，这套设计放弃了一些短期效率，也留下了没有完全解决的问题。

- **审计成本固定占用预算。** 审计样本大概率不产生发现，这是为可估漏报付出的代价。审计份额设多少，目前只有原则，没有普适数值，需要按任务试出来。
- **选择偏差只能部分纠正。** 记录最终入选概率可以在统计上重加权，但无法恢复入选概率为零的区域。生成侧的独立覆盖是唯一缓解手段，它本身也可能被优化掉。
- **根因归类仍依赖人工或工具证据。** 这一层没有自动化的可靠替代方案，因此主指标必须把“已确认根因”和“未确认行为簇”分开报告。
- **窗口长度与噪声的矛盾。** 窗口太短无法区分收益与波动，太长则信用分配滞后，多个改动叠加。折中方案是限制同一窗口的改动数量，并保留待决状态。
- **自我修改的搜索空间没有边界。** 组件可以提出任何更新，包括修改自己的评估参与方式。当前只用“证据不可改写”和“旧版判定”两条边界约束，更强的约束需要在实际事故中积累。
