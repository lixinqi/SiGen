# 动机与设计取舍

这份文档写给没参与过任何前期讨论的读者。它回答三个问题：为什么这件事值得做（WHY），做出来的东西是什么（WHAT），它是怎么运转的（HOW）。读完后你应当能自己判断这套设计是否成立，也能指出它哪里会失败。

## WHY：为什么要做这样一个系统

### 从一个具体场景说起

有两个软件：A 是在研产品，B 是成熟的竞对。团队要弄清 A 在哪些负载下落后于 B、落后多少。把这个需求翻译一下，它其实是一个搜索问题：候选测试的空间几乎无限，真正有价值的只是其中能稳定暴露差距的那一小部分，要把它们从空间里找出来。

朴素做法是生成一大批候选测试，在 A 和 B 上各跑一遍，筛出有差距的，反馈给生成器。这条路能走通，但账算不过来。真实实验是昂贵的：部署环境、构造初始数据状态、在对照系统上跑同一份测试、多轮重复测量，每一轮都消耗机器与时间。而生成空间几乎是无限的，绝大多数候选跑完什么差距都没有。钱花在了没有信息量的实验上。

于是自然想到加一个预判器：先用模型预测哪些候选可能暴露短板，只跑预测为真的。这就是自进化设想的起点——预判器从运行结果里学习，越学越准，实验越跑越省。

### 硬过滤会毁掉这个设想

如果预判器的预测直接变成执行与否的开关，系统会陷入一个自证的循环：

1. 预判器认为某类测试不会是短板，这类测试永远得不到物理真值。
2. 预判器无从知道自己漏掉了什么，假阴性不断积累。
3. 生成器逐渐迎合预判器，只生产预判器喜欢的样本。
4. 在筛剩下的样本上，预判准确率越来越高。
5. 但真正有价值、超出当前认知的短板，连执行机会都没有。

每个组件的指标都在变好，系统的真实发现能力却在下降。注意这不是模型不够准的问题——再准的模型也解决不了，因为问题出在**被否决的对象拿不到真值**。判断一旦是终局，判断者就永远学不到自己的错误。

### 同样的问题出现在每一个做判断的组件上

把系统往完整了想，做判断的不止预判器：

- **去重器**判断一个候选是否带来新信息。它若判为重复就丢弃，被丢的样本同样没有真值。它可能误合并——两个只差一个参数的测试，恰好跨过缓存冷热边界，物理行为截然不同，却被折叠成一个。也可能走向反面，越来越严格地把所有新候选都归入已有簇，系统看起来稳定、成本低廉，实际已经停止探索。
- **审核器**判断一次对系统自身的修改是否值得接受。它误放了一个坏更新，后续退化会让它学到教训。但它误杀了一个好更新，而这个更新从此不再被尝试，它永远不知道自己过于保守。只从误放中学习的审核器，最安全的进化方向是拒绝一切——指标上“没有退化”，实际上系统已经停止进化。

三个组件，三种判断，同一个病根：**判断被当成终局**。灾难性遗忘只是这个病的症状之一，而且不是最隐蔽的那个。

### 关键的观察

把所有失败模式摆在一起，会发现它们共享一个结构：组件做了判断，判断直接决定了对象的命运，对象从此没有机会提供真值，组件于是无法校准。

反过来，解法也共享一个结构：让组件在判断之外声明自己有多少把握，把握不足的地方不要把判断当终局，而是花一点真实成本去试探。试探的结果回流，判断就有了修正的依据。

这就是整个系统真正的设计起点。它不是“给实验流程加几个智能体”，而是**给每一种判断都接上真值回路**。

## WHAT：做出来的东西是什么

### 统一判定接口

系统里所有做判断的组件，输出形态统一为两个浮点数：

- **判定值 v**：对“这个对象值得为它付出真实成本”的预测，取值 0 到 1。方向在所有组件间统一：越大越倾向通过。
- **置信度 c**：这个判定值有多少历史经验支撑，取值 0 到 1。它不是语气上的确定程度，而是从同类对象的历史误判率、相似案例数量与结果一致性里校准出来的数值。低置信度是组件在声明：这类对象我没判对过几次。

判定值的语义随组件不同：

| 组件 | 判定值的含义 | 低置信度时上层怎么做 |
| --- | --- | --- |
| 预判器 | 该候选会出现稳定短板的概率 | 仍然安排物理运行 |
| 去重器 | 该候选会带来新信息的概率 | 保留样本，必要时运行对照 |
| 审核器 | 该更新会带来净收益的概率 | 探索性接受，试行并评估 |

组件只负责判断，把判断变成动作是上层的统一调度。高置信时按判定值执行或拒绝；低置信时提高探索性执行的概率；高置信否决也保留一个小概率的随机审计。每次决策都记下当时的探索概率，事后才能区分“按判断做出的选择”和“为了获取真值做出的探索选择”——缺了这个记录，误杀率就估不出来。

这个接口替代的是三套各自为政的机制：预判器外面的抽样复审、去重器外面的边界保留、审核器外面的反事实回放。现在它们是一种机制：**给出判断，标明经验边界，在边界处探索，用真实结果纠正判断**。

### 判断与真值放进同一条档案

每一次判断留下一条完整档案：谁判的（组件及版本）、判的什么（对象标识）、判定值与置信度、上层怎么决定的（含探索概率）、真值是什么。真值分两种状态——未到达与已到达，未到达的档案不参与校准，否则“没跑过”会被当成“判对了”。

档案一旦写入不可改写，真值到达只追加不覆盖。这条约束针对一种具体的作弊：组件修改了指标计算或成功定义，让自己过去的判断看起来一直正确。所有实现都可以进化，物理观测的完整性与本轮评估的事务边界不能被当次更新事后改写。

### 两个时间尺度的循环

系统包含两个循环，它们的反馈密度完全不同，分开设计：

**快循环——实验学习**。生成候选 → 预判与去重 → 调度 → 物理测量 → 真值回流。每跑一次实验就有反馈，数据充足。

**慢循环——harness 学习**。修改某个组件 → 经历一个观察窗口 → 评估系统发现能力 → 给更新分配信用。一次窗口评估可能对应多个修改，修改之间还会交互，数据非常稀疏。整个系统里最难的不是预测物理结果，而是慢循环里的更新级信用分配，这也是审核器不能轻易假设会成功的原因。

### 生成器为什么不在接口里

生成器是实验策略，它生产被判断的对象，自己不做判断。这个分工是刻意的。如果生成器同时给自己打分，它很快就会学会生产“看起来会被预判为真”的测试——Goodhart 定律的标准剧情。所以生成器的最终奖励只能来自物理结果：真实运行确认的、去重后的、可复现的新根因。预判器和去重器的分数可以帮它排序，不能当它的奖励。

## HOW：系统怎么运转

### 一轮实验怎么跑

1. **生成**。生成器从经验库读物理结果（注意：不是读预判器分数），生成一批候选，每个候选带生成依据与经验来源。候选数量大于真实执行预算。
2. **预判**。预判器对每个候选预测配对差距的方向、幅度与方差，填出判定值；置信度调用共享校准，从同类负载的历史档案里算，不自报。
3. **去重**。去重器按访问轨迹、操作比例、初始状态、缓存冷热、并发时序找邻居，把候选分成冗余重复、受控变体、语义新样本三类。受控变体——只差一个关键变量的近重复——必须被认出来保留，跨过边界的突变点只能靠它们发现。
4. **调度**。统一调度读每个候选的判定值与置信度，在预算内做选择：高置信高价值的先跑，低置信的多给探索机会，高置信否决里按小概率抽审计样本。
5. **测量**。选中的候选在目标与对照两侧配对执行：相同初始状态、多轮重复、交错顺序、先校验正确性再比性能、按噪声判显著性。未确认的结果同样是真值，照样回流。
6. **回流**。每条判定连同真值写入经验库。预判器从这里知道自己漏了什么，去重器从这里知道自己误合并、误拆分了什么。

### 一次更新怎么审

1. 任一组件提出更新：目标、基础版本、完整 diff、声称要解决的问题。缺了声称，窗口评估就没有检验标准。
2. 审核器检查更新：是否修改了审核逻辑自身、是否改变样本筛选导致评估分布变化、是否修改指标计算让分数虚高。然后给出判定值与置信度，置信度从自己的误判史里校准——误放史与误杀史都要参考。
3. 上层按置信度决定：高置信按判定值接受或拒绝；低置信按探索概率让一部分更新照样试行。试行与接受一样进入观察窗口。
4. 窗口结束后评估：窗口内主指标与同预算对照的差距、旧能力是否退化。一次窗口引入多个修改时，靠回放与消融补做归因。
5. 信用结论分四种：判定被证实、误放、误杀、置信度虚高。结论回流给审核器，成为它校准自己的材料。

### 置信度从哪来

置信度是整个机制的要害，也是最容易被糊弄的地方。让组件自报一个 confidence 是行不通的——它完全可能在没经验时输出 0.95，探索机制随即失效。

所以置信度由一个共享的校准操作统一计算：统计同类对象的历史判定档案里，相似案例有多少、结果是否一致、历史误判率多少；当前对象落在从没判过的区域时，返回接近零的值。判定值学习“对象值不值得”，置信度学习“我关于这类对象的判断通常有多可靠”，两者都由后续真值持续修正。

### 探索不是免费的

探索性执行与正常利用占用同一种真实执行预算。每批决策有一个探索预算上限，低置信探索和高置信审计都从这里出。这意味着探索率本身就是一个需要被评估的设计参数：太少，系统封闭；太多，发现效率被稀释。评估方案见 `docs/evaluation.md`。

## 设计取舍

**为什么不用硬过滤加事后补救。** 补救机制（抽样复审、反事实回放）挂在判断外面，每一类判断要各挂一套，而且补救的预算、时机、记录格式各不相同，最后谁也说不清整个系统的真值覆盖率。统一接口把探索写进判断的决策路径里，一种机制覆盖所有组件，记录格式天然一致。

**为什么不把审核器隔离出去。** 隔离能保证审核逻辑不被被审对象污染，但也让审核器看不到自己的实现与判断历史，识别不了“这次更新改了我自己的否决逻辑”这类问题。正确的要求不是隔离，而是可归因：每个判断能定位到具体的审核器版本，每次自我修改后归因链不断，且当前更新不能改写自己的成功定义。这是事务一致性要求，不要求物理隔离。

**为什么判定值方向必须统一。** 如果去重器的判定值是“冗余的概率”而其他组件是“值得执行的概率”，上层调度就要记住每个组件的极性，接错一次就是系统性 bug。统一成“越大越倾向通过”，调度代码不需要知道判定来自哪个组件。

**为什么被去重的样本不删除。** 纯重复样本留作复现、回归与预判器校准，只是不计为新发现、不默认占用探索预算。删除会丢掉校准材料，还会在事后争议时无法复核。

## 这套设计不解决什么

诚实的边界比能力的宣称更重要。

**慢循环的信用分配仍然很难。** 一次窗口对应多个修改时，归因靠回放与消融补做，这本质上是小样本因果推断，没有银弹。设计能做的是把证据留全——diff、声称、判定、探索概率、窗口结果——让归因至少有据可依。

**置信度有冷启动问题。** 系统上线初期没有任何历史档案，所有置信度都接近零，所有判断都走探索。这实际上是一种设计好的行为：系统在没经验时表现得像没有预判器的传统方案，随着真值积累才逐渐把调度权交给组件。

**物理噪声不可消除。** 测量协议（多轮重复、交错顺序、缓存控制、显著性判断）能压缩噪声的影响，不能消除它。预判器学到的规律里总会混着环境偏差，这是把“超过噪声才计为短板”写进测量协议而不是写在分析报告里的原因。

**它不保证自进化一定值得。** 这一点要写进证伪条件，而不是写进宣传材料。见 `docs/evaluation.md`。
